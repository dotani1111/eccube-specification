# EF10_返品申請_結合試験項目書

### 事前準備

対象機能: [EC-CUBE/ec-cube#6838](https://github.com/EC-CUBE/ec-cube/pull/6838)

- 会員A・会員B の 2 会員を登録し、ログインできる状態にしておく
- 会員A で商品P（返品可。`dtb_product.refund_allowed` は既定で true）を数量 2 で購入し、管理画面の受注編集で対応状況を「発送済み」に変更する（以下「対象受注」）
- 会員A で別の受注を作成し、対応状況を「新規受付」のままにしておく（以下「未発送受注」）
- 返品不可商品Q を用意する。管理画面に設定項目はないため DB で `UPDATE dtb_product SET refund_allowed = false WHERE id = <商品QのID>;` を実行し、会員A で商品Q を購入した受注を「発送済み」にしておく
- PHP の `upload_max_filesize` と `post_max_size` を 16M 以上（例: 32M）に設定する（15MB 超ファイルの試験で PHP 側の制限に先に掛からないようにするため）。Apache（mod_php）では EC-CUBE ルートの `.htaccess` にある `php_value post_max_size 10M` / `php_value upload_max_filesize 10M` が php.ini より優先されるため、`.htaccess` の値も同じく書き換える
- 管理画面の 設定 > 店舗設定 > 基本設定 の「送信元メールアドレス(From)」を受信確認できるメールアドレスにしておく（通知メールの宛先になる）
- 添付用ファイルを用意する: JPEG / PNG / GIF / WebP の画像、MP4 の動画、15,000,000 バイトを超える GIF 画像（例: 16MB）、許可外形式のファイル（.txt / .pdf）
- 添付ファイルの直リンク試験（EF1001-UC03-T03）は Apache 環境で実施する（`html/upload/refund_request/.htaccess` による拒否）
- エラー画面の文言（「アクセスできません。」「ページがみつかりません。」など）を確認する項目は `APP_ENV=prod` で実施する（`APP_ENV=dev` ではエラー画面のテンプレートが使われず、Symfony のデバッグ用画面が表示される）
- 一時ファイルの掃除コマンド（EF1001-UC06）と既存環境のアップグレード（EF1002-UC06）はサーバーのコンソール操作を含む

## EF1001-UC01-T04_返品申請（入力→確認→完了・添付なし）

1. TOPページ(会員Aでログイン状態)→マイページ→ご注文履歴→対象受注の[詳細を見る]
1. 商品Pの[返品申請]ボタンを押下する

1. 入力項目として「返品希望数量」（必須）、「返品理由」（必須、プレースホルダ「返品理由を入力してください」）、「証拠ファイル」が表示される

1. 返品希望数量に「1」、返品理由に改行を含む文章を入力し、[確認画面へ]ボタンを押下する
1. 返品申請内容確認画面が表示され、見出しに「返品申請内容確認」、商品名、返品希望数量「1」、入力した返品理由（改行が保持される）が表示される
1. 証拠ファイルの欄は表示されない
1. [申請する]ボタンを押下する
1. 返品申請完了画面が表示され、見出しに「返品申請完了」、「返品申請を受け付けました」「返品申請の内容を確認のうえ、ご連絡いたします。しばらくお待ちください。」と表示される
1. [マイページへ戻る]ボタンを押下する
1. マイページ/ご注文履歴画面に遷移する
1. 管理画面＞受注管理＞返品申請管理に、対象受注・会員A・商品P・ステータス「新規申請」の申請が 1 件表示される
